# 各语言的应用范围

这个仓库把多种语言放在一起，是为了对照，不是因为存在某个产品必须同时用上它们。真实工程里，一门语言通常只守一层：离硬件近的守性能和资源，托管语言守业务，标记语言守给人看的结构。

下面按这个仓库里出现的语言来写。HTML 和 Markdown 是标记语言，负责描述结构；其余是编程语言，负责计算和行为。

## C

C 直接面对内存、指针和硬件寄存器，标准库很小，生成的机器码也少。操作系统、启动代码和设备驱动需要这种可预测性：没有垃圾回收突然停顿，也没有隐藏的运行时。

常见落点：

- 操作系统内核和引导程序，例如 Linux 内核的主体
- 单片机、固件、实时系统，内存往往以 KB 计
- 网卡、磁盘、GPU 以外的设备驱动
- 数据库存储引擎、网络协议栈、压缩和加密库
- 别的语言的运行时本身，CPython、CRuby、许多 JVM 的本地部分都由 C 写成

C 也是跨语言的公共边界。别的语言要调用系统或复用老库，通常先做成 C ABI，再由各自的外部函数接口去接。所以即使用 Rust 或 Python 写新代码，底下仍可能留着一块 C。

它适合接口长期稳定、资源账必须自己算清的层。界面、经常改规则的业务、以及希望编译器默认拦住内存错误的新项目，一般会放到更高一层。

## C++

C++ 保持接近硬件的性能，同时提供类、模板、RAII 和标准库容器。代价是语言很大，构建慢，对象生命周期要自己理清。它出现在“抽象已经很复杂，但每一层都不能付运行时税”的地方。

常见落点：

- 游戏引擎和三维工具，场景图、渲染、物理、动画
- 浏览器里解析、排版和图形之外的重计算部分
- 编译器基础设施，例如 LLVM
- 音视频编解码、CAD、工业仿真、机器人控制
- 高频交易和行情处理里对延迟敏感的进程
- 大型客户端：办公软件、设计软件、部分数据库

和 C 的分工很稳定。C 提供稳定的二进制接口和最小运行时；C++ 在进程内部组织复杂对象。一个游戏引擎常常是 C++，对外插件或和操作系统说话时仍走 C 接口。玩法脚本则再交给 C#、Lua 或蓝图，避免每改一个数值都去编译引擎。

## C#

C# 跑在 .NET 上，有垃圾回收、强类型和完整的标准库，工具链从编译、包管理到调试是一套。它在微软技术栈里最完整，同时早就是跨平台语言。

常见落点：

- 企业后台、内部系统和与 Windows、Azure 绑在一起的服务
- 桌面工具，尤其是要深度使用 Windows API 的管理端
- 游戏玩法。Unity 的脚本是 C#，引擎底层仍是 C++
- 编辑器、导入器、构建辅助这类给开发者用的工具
- 要求类型清楚、又希望迭代速度高于 C++ 的中大型应用

和 Java 同属托管、长驻进程的一类。选 C# 通常是因为团队、运行时或产品已经在 .NET 上：Unity 项目、Windows 桌面、现有的 ASP.NET 服务。选 Java 则更多是因为 JVM 上的中间件、Android 或已有的 Java 服务集群。

## Java

Java 的单位是长期运行的服务。JVM 负责内存、线程和即时编译，语言本身把类型和包边界写得很明确，适合很多人一起维护的大型代码库。

常见落点：

- 银行、电信、电商的核心后台和中台
- 消息、检索、协调类中间件。Kafka、Elasticsearch、ZooKeeper 的实现语言都是 Java
- Hadoop 一系的大数据处理
- Android 应用的历史存量；新代码经常改用 Kotlin，但运行的仍是 Android 上的 JVM 字节码，库和框架大量是 Java
- 需要稳定发布节奏的大型业务系统

Java 不拿去写固件，也不拿去写浏览器里的页面。计算特别热的内层循环，有时会通过 JNI 下沉到 C 或 C++，业务编排仍留在 Java。

## Python

Python 把表达写短，把执行交给解释器。标准库覆盖文件、进程、网络和测试，第三方库覆盖科学计算和机器学习。它的位置通常是“把别的系统粘起来”，以及“人比机器更贵”的分析工作。

常见落点：

- 一次性脚本、安装流程、测试夹具、运维自动化
- 数据清洗、统计、可视化和实验记录
- 机器学习的研究和训练。PyTorch、NumPy 的耗时部分是 C、C++ 或 CUDA，Python 负责把步骤串起来
- 中小型 Web 服务、内部接口、任务队列
- 教学和原型，因为读一遍就能看见控制流

热点路径若必须压延迟或压内存，会把内层换成 C、C++ 或 Rust，外层继续用 Python 调度。浏览器里的交互、内核、单片机固件，都不在它的主场。

## Rust

Rust 用所有权在编译期约束内存和并发，目标是做到接近 C 和 C++ 的性能，同时少一类释放错误和数据竞争。没有垃圾回收的停顿，二进制也可以单独部署。

常见落点：

- 命令行工具和开发者基础设施
- 网络服务、代理、边缘节点，延迟和内存都要稳
- 浏览器组件。Firefox 里不少新模块用 Rust 写
- 操作系统的新组件、嵌入式里对安全性要求高的部分
- 编译到 WebAssembly，嵌进网页或插件系统
- 替换一块已经证明容易出错的 C 或 C++ 库，而不是推倒整个老系统

它适合会长期运行、出错代价高的基础设施。一天改许多次的表单和审批流可以写，但编译时间和所有权模型会拖慢这种改动。那些地方 C#、Java 或 Python 更顺手。

## JavaScript

浏览器里的程序行为几乎都由 JavaScript 承担。页面上的校验、请求、动画和状态更新都从这里出发。Node.js 把同一门语言带到服务器和构建脚本之后，它也负责打包工具、接口层和一些全栈应用。

常见落点：

- 网站和 Web 应用的交互
- 构建工具、代码转换、开发服务器
- 用 Node.js 写的接口、实时服务和脚本
- Electron 一类桌面壳，界面仍是网页技术，系统能力通过绑定去调
- 小程序和混合应用里与页面相关的逻辑

它和 HTML 的边界是：HTML 给出结构和语义，JavaScript 在结构已经存在之后去改它、听事件、取数据。性能极敏感的图像或编解码，会把模块编译成 WebAssembly，调用方仍是 JavaScript。

## HTML

HTML 描述一份文档由什么组成：标题、段落、列表、链接、图片、表单和按钮。浏览器按这些标记画出页面，读屏软件也靠它们理解层次。它不计算，不保存业务规则。

常见落点：

- 所有网站的页面骨架
- 邮件里允许的那一部分富文本
- 组件框架最终要交给浏览器的那棵节点树
- 强调语义和无障碍的内容页、文档站

样式交给 CSS，行为交给 JavaScript。服务端可以生成 HTML，但生成出来的仍然是这份结构，而不是另一门编程语言。

## Markdown

Markdown 用很少的符号表示标题、列表、链接和代码，源文件本身就能读。渲染之后通常变成 HTML。它的读者首先是人，其次才是静态网站生成器或编辑器。

常见落点：

- 仓库里的 `README`、变更记录和贡献说明
- 技术文档站的源稿
- 问题讨论、合并请求和评论
- 笔记、说明书和博客草稿

它覆盖不了复杂版式、交互控件和精确定位。那些内容要回到 HTML，或者交给专门的排版系统。程序逻辑也不写在 Markdown 里；这里适合放说明、步骤和约定。

## Haskell

Haskell 是纯函数式语言：默认没有副作用，类型系统很强，求值是惰性的。用它写代码时，会把规则写成类型和函数，把输入输出推到边缘。这使它擅长规则密集、正确性比开发速度更重要的核心。

常见落点：

- 编译器和语言工具。GHC 自身主要用 Haskell 写成，Pandoc 用它做文档转换
- 金融和保险里的定价、合约和风控规则，常做成内部的小语言
- 需要把不变量刻进类型里的原型和核心库
- 编程语言研究，以及影响别的语言的类型系统设计

它的工业份额小，库和招聘都比 Java、C# 窄。团队里没有人打算长期维护时，不适合拿它做普通的后台或页面。它的价值集中在那一块“规则不能写错”的核心，周围的接口、存储和界面仍由别的语言完成。

## 放在同一个系统里时怎么分工

没有项目被要求把以上语言全部用上。比较常见的是两三层叠在一起，例如：

| 层 | 更常见的选择 | 这一层在干什么 |
| --- | --- | --- |
| 设备与内核 | C | 寄存器、驱动、固件 |
| 引擎与重计算 | C++ | 渲染、物理、编解码、编译器 |
| 长期运行的业务服务 | Java 或 C# | 事务、权限、工作流 |
| 玩法或桌面工具 | C# | 在现成引擎或 .NET 上写逻辑 |
| 分析与自动化 | Python | 脚本、数据、模型编排 |
| 新的基础设施 | Rust | 既要性能也要内存安全的进程 |
| 页面 | HTML 加 JavaScript | 结构与交互 |
| 说明 | Markdown | 给人读的文档 |
| 规则核心 | Haskell | 类型能托住的那一块计算 |

这个模板里的示例故意做了同一件小事，方便对照语法和构建方式。真正选型时，先问这段代码要守的是时间、内存、人数、还是文档，再从上面的层里取一门。
